# 要件: ダイビングログの記録・閲覧・編集・削除

関連: [設計](./design.md) / [概要](../00-overview.md) / [写真添付](../photo-attachment/requirements.md) / [ガイドサイン](../guide-signature/requirements.md)

## 概要

1本のダイビングを1件の「ダイビングログ」として記録する。基本情報・環境情報・器材/エア管理・写真・ガイドサインを1つのレコードにまとめて保存し、一覧・詳細・作成・編集・削除ができる。

## 項目定義

| 分類 | 項目 | 必須 | 型 |
| --- | --- | --- | --- |
| 基本情報 | 日付 (date) | ○ | 日付文字列 (YYYY-MM-DD) |
| 基本情報 | 開始時刻 (startTime) | - | 時刻文字列 |
| 基本情報 | エリア名 (area) | - | 文字列 |
| 基本情報 | ダイビングポイント名 (siteName) | ○ | 文字列 |
| 基本情報 | 最大水深 m (maxDepth) | - | 数値 |
| 基本情報 | 潜水時間 分 (duration) | - | 数値 |
| 環境情報 | 水温 ℃ (waterTemp) | - | 数値 |
| 環境情報 | 透明度 m (visibility) | - | 数値 |
| 環境情報 | 天候 (weather) | - | `sunny` / `cloudy` / `rainy` / `other` |
| 環境情報 | 流れ (current) | - | `none` / `weak` / `moderate` / `strong` |
| 器材・エア | ドライスーツ (drySuit) | - | 選択リスト（プリセットからの単一選択・未選択可） |
| 器材・エア | ウェットスーツ (wetSuit) | - | 選択リスト（プリセットからの単一選択・未選択可） |
| 器材・エア | フード (hood) | - | 真偽値（着用有無） |
| 器材・エア | フードベスト (hoodVest) | - | 真偽値（着用有無） |
| 器材・エア | アルミタンク (aluminumTank) | - | 選択リスト（プリセットからの単一選択・未選択可） |
| 器材・エア | スチールタンク (steelTank) | - | 選択リスト（プリセットからの単一選択・未選択可） |
| 器材・エア | タンク開始圧力 bar (tankStartPressure) | - | 数値 |
| 器材・エア | タンク終了圧力 bar (tankEndPressure) | - | 数値 |
| 器材・エア | ウェイト kg (weight) | - | 数値 |
| 写真・メモ | バディ名 (buddyName) | - | 文字列 |
| 写真・メモ | メモ (notes) | - | 複数行文字列 |
| 写真・メモ | 写真 | - | [photo-attachment](../photo-attachment/requirements.md) を参照 |
| ガイドサイン | ガイド名 (guideName) | - | 文字列 |
| ガイドサイン | サイン | - | [guide-signature](../guide-signature/requirements.md) を参照 |

エリア名 (area) は、ダイビングポイント名 (siteName) より広い地理的な単位（例: エリア名「石垣島」／ダイビングポイント名「マンタスクランブル」）を表す自由記述の任意項目。両者は互いに独立した項目であり、システムはエリアをマスタ（一覧・選択肢・CRUD画面を持つ管理対象）として扱わず、エリアとダイビングポイントの階層関係も強制しない。過去ログの入力値を再利用する「参照」操作（REQ-8）は、この自由記述入力を補助するものであり、マスタ管理機能ではない。

### 廃止された項目

| 分類 | 項目 | 状態 |
| --- | --- | --- |
| 器材・エア | 使用器材 (gear) | 廃止。ドライスーツ／ウェットスーツ／フード／フードベスト／アルミタンク／スチールタンクの構造化項目に置き換える（REQ-6.9, REQ-6.10） |

### 器材の選択肢（プリセット）

選択リストの選択肢はアプリに固定で埋め込む（REQ-6.2, REQ-6.3）。表示ラベルは以下とする。内部の値・型定義は [設計](./design.md) を参照。

| 項目 | 選択肢（先頭は常に「選択なし」） |
| --- | --- |
| ドライスーツ | 選択なし / インナー薄手 / インナー中厚 / インナー厚手 |
| ウェットスーツ | 選択なし / 3mm / 5mm / 5mm + タッパー / セミドライ |
| アルミタンク | 選択なし / 10L / 11L / 12L |
| スチールタンク | 選択なし / 10L / 12L / 14L |

上記の選択肢はユーザー確認済みの確定版（[確定した判断ポイント](#確定した判断ポイントユーザー確認済み) を参照）。将来、実際の器材構成と合わなくなった場合は本表と [設計](./design.md) の選択肢定義を合わせて更新する。

## 要件（EARS形式）

### 一覧表示
- REQ-1.1: システムは、保存済みの全ダイビングログを日付の新しい順に一覧表示するものとする。
- REQ-1.2: 保存済みログが0件のとき、システムは一覧の代わりに空状態メッセージ（「まだ記録がありません。」）を表示するものとする。
- REQ-1.3: 一覧の各行には、日付・ダイビングポイント名に加え、値が存在する場合のみエリア名・最大水深・潜水時間・写真枚数・サイン済みマークを表示するものとする。
- REQ-1.4: ユーザーが一覧の行を選択したとき、システムは該当ログの詳細画面へ遷移するものとする。
- REQ-1.5: エリア名が入力されているとき、システムは一覧の各行でダイビングポイント名と同じ行にエリア名を併記するものとする（エリア名が未入力のときは、エリア名用の表示領域自体を出力しない）。
- REQ-1.6: システムは、一覧の各行に器材・エア管理カテゴリの項目（スーツ・フード・タンク種別・ウェイト・タンク圧力）を表示しないものとする。

### 新規作成
- REQ-2.1: ユーザーが「新規記録」を選択したとき、システムは日付を本日日付で初期化した入力フォームを表示するものとする。このとき、REQ-7（同日ログからの引き継ぎ）が適用される項目を除き、全項目を未入力とするものとする。
- REQ-2.2: 日付とダイビングポイント名が未入力のとき、システムはフォームの送信を許可しないものとする（HTML必須項目バリデーション）。
- REQ-2.3: ユーザーが入力フォームを送信したとき、システムは新しいダイビングログをローカルデータベースに保存し、作成日時・更新日時を現在時刻で記録するものとする。
- REQ-2.4: 保存が完了したとき、システムは作成されたログの詳細画面へ遷移するものとする。
- REQ-2.5: ユーザーが入力中に「キャンセル」を選択したとき、システムは入力内容を破棄して、フォームを開く前の画面へ戻るものとする（[marine-life-observation REQ-11.12](../marine-life-observation/requirements.md) により、戻り先は履歴上の直前の画面である。一覧から新規作成した場合は一覧画面、詳細画面から編集を開始した場合はその詳細画面に戻る）。
- REQ-2.6: システムは、入力フォームの基本情報にエリア名の自由記述テキスト入力欄を、ダイビングポイント名とは別の任意入力項目として提供するものとする。入力の主手段は自由記述とし、過去ログの値からの選択は REQ-8 に定める補助的な「参照」操作としてのみ提供する（入力を選択肢に限定するプルダウン化・入力時の自動補完は行わない）。
- REQ-2.7: エリア名が未入力のとき、システムはフォームの送信を妨げず、エリア名を値なしとして保存するものとする。

### 詳細表示
- REQ-3.1: システムは、詳細画面にログの全項目を分類（基本情報／環境情報／器材・エア管理／写真・メモ／ガイドサイン）ごとに表示するものとする。
- REQ-3.2: 値が未入力の項目は、システムは「-」または空扱いとして表示するものとする。
- REQ-3.3: 対象のログが存在しない（削除済みなど）とき、システムは「記録が見つかりませんでした。」を表示するものとする。
- REQ-3.4: システムは、詳細画面の基本情報セクションにエリア名を表示するものとする（未入力の場合は REQ-3.2 に従い「-」を表示する）。

### 編集
- REQ-4.1: ユーザーが詳細画面で「編集」を選択したとき、システムは既存の値で初期化された入力フォームを表示するものとする。
- REQ-4.2: ユーザーが編集内容を送信したとき、システムは該当ログを更新し、更新日時を現在時刻で上書きするものとする（作成日時は変更しない）。
- REQ-4.3: 更新が完了したとき、システムは詳細画面へ遷移するものとする。
- REQ-4.4: エリア名を持たない既存ログ（本項目の追加以前に作成されたログ）を編集するとき、システムはエリア名を未入力として初期化し、そのまま保存できるものとする（データ移行やエリア名の入力強制は行わない）。
- REQ-4.5: 器材の構造化項目（ドライスーツ／ウェットスーツ／フード／フードベスト／アルミタンク／スチールタンク）を持たない既存ログを編集するとき、システムは各項目を未選択・未着用として初期化し、そのまま保存できるものとする（データ移行や入力強制は行わない）。
- REQ-4.6: 廃止された「使用器材 (gear)」に値を持つ既存ログを編集・保存したとき、システムはその値をデータベース上に保持し続けるものとする（消去・他項目への自動変換は行わない）。

### 削除
- REQ-5.1: ユーザーが詳細画面で「削除」を選択したとき、システムは削除前に確認ダイアログを表示するものとする。
- REQ-5.2: ユーザーが削除を確定したとき、システムは該当ログおよびそれに紐づく添付（写真・サイン画像）をすべて削除するものとする。戻り先は、[marine-life-observation REQ-11.13](../marine-life-observation/requirements.md) により「削除前に見ていた画面（削除したログを対象とする履歴のエントリをすべて取り除いた直近の画面。残るエントリがなければ一覧画面）」に改められる。
- REQ-5.3: ユーザーが確認ダイアログをキャンセルしたとき、システムは何も削除せず詳細画面に留まるものとする。

### 器材・エア管理の入力項目
- REQ-6.1: システムは、器材・エア管理カテゴリの入力項目として、ドライスーツ・ウェットスーツ・フード・フードベスト・アルミタンク・スチールタンク・タンク開始圧力・タンク終了圧力・ウェイトを、この順で提供するものとする。
- REQ-6.2: システムは、ドライスーツ・ウェットスーツ・アルミタンク・スチールタンクを、アプリが定義する固定のプリセット選択肢からの単一選択として提供するものとする（自由記述による入力・複数選択は許可しない）。
- REQ-6.3: システムは、ユーザーが選択肢そのものを追加・編集・削除する機能を提供しないものとする（選択肢の変更は本仕様の更新とアプリの更新によってのみ行う）。
- REQ-6.4: システムは、各選択リストに「選択なし」を用意し、既定値を「選択なし」とするものとする。「選択なし」で保存されたときは、システムは当該項目を値なしとして保存するものとする。
- REQ-6.5: システムは、フードおよびフードベストを着用有無のチェックボックスとして提供し、チェックありを「着用」、チェックなしを「着用なし」として保存するものとする。
- REQ-6.6: システムは、ドライスーツとウェットスーツの同時選択を許可するものとする（排他制御・警告・自動クリアは行わない）。
- REQ-6.7: システムは、アルミタンクとスチールタンクの同時選択を許可するものとする（排他制御・警告・自動クリアは行わない）。
- REQ-6.8: 器材・エア管理カテゴリの全項目は任意入力とし、未入力・未選択・未チェックのままでもフォームの送信を妨げないものとする。
- REQ-6.9: システムは、廃止された「使用器材 (gear)」の自由記述入力欄を入力フォームに提供しないものとする。
- REQ-6.10: 廃止された「使用器材 (gear)」に値を持つ既存ログの詳細画面を表示するとき、システムはその値を読み取り専用の補足情報として器材・エア管理セクションに表示するものとする（値を持たないログでは、この表示領域自体を出力しない）。
- REQ-6.11: システムは、詳細画面の器材・エア管理セクションに REQ-6.1 の各項目を表示するものとする。選択リスト項目が値なしのときは「-」、フード・フードベストは着用時のみ「着用」、着用なしのときは「-」を表示するものとする。

### 同日の直前ログからの引き継ぎ
- REQ-7.1: ユーザーが「新規記録」を選択したとき、システムはフォームの初期日付（本日日付）と同じ日付を持つ保存済みログを検索し、1件以上見つかった場合は、そのうち1件（REQ-7.3）の引き継ぎ対象項目（REQ-7.4）の値を新規フォームの初期値としてコピーするものとする。
- REQ-7.2: システムは、「同じ日付」の判定を日付 (date) 文字列（YYYY-MM-DD）の完全一致のみで行うものとする（前日・翌日や開始時刻は考慮しない）。
- REQ-7.3: 同じ日付のログが複数件あるとき、システムは更新日時 (updatedAt) が最も新しい1件を引き継ぎ元として選ぶものとする（更新日時が同値のときはIDが大きいものを選ぶ）。
- REQ-7.4: 引き継ぎ対象項目は、エリア名・ドライスーツ・ウェットスーツ・フード・フードベスト・アルミタンク・スチールタンク・ウェイト・ガイド名・バディ名のみとするものとする。
- REQ-7.5: システムは、日付・開始時刻・ダイビングポイント名・最大水深・潜水時間・水温・透明度・天候・流れ・タンク開始圧力・タンク終了圧力・メモ・写真・ガイドサイン画像を引き継がないものとする（これらは REQ-2.1 のとおり未入力のままとする）。
- REQ-7.6: 引き継ぎ元のログで引き継ぎ対象項目が未入力・未選択だったとき、システムは新規フォームの当該項目も未入力・未選択とするものとする。
- REQ-7.7: 引き継ぎを行ったとき、システムはフォーム上に引き継ぎが発生したこと（および引き継ぎ元の日付）を示すメッセージを表示するものとする。
- REQ-7.8: 引き継ぎでコピーされた値について、システムはユーザーによる変更・クリアを妨げないものとする（引き継ぎ値は初期値にすぎず、保存時に特別扱いしない）。
- REQ-7.9: 同じ日付のログが1件も存在しないとき、システムは引き継ぎを行わず、REQ-2.1 のとおり日付以外が未入力のフォームを表示するものとする。
- REQ-7.10: ユーザーがフォーム上で日付を変更したとき、システムは引き継ぎを自動で再実行しないものとする（入力途中の値を自動で上書きしない）。
- REQ-7.11: システムは、新規作成フォームの器材・エア管理セクションに「同じ日付の直前のログから引き継ぐ」操作を提供し、ユーザーがこれを選択したとき、その時点でフォームに入力されている日付を基準に REQ-7.2〜REQ-7.6 と同じ引き継ぎを実行し、引き継ぎ対象項目を上書きするものとする。
- REQ-7.12: その時点の日付に該当するログが存在しないとき、システムは REQ-7.11 の操作を選択できない状態（無効表示）にするものとする。
- REQ-7.13: 既存ログの編集時（REQ-4.1）は、システムは引き継ぎを行わず、REQ-7.11 の操作も提供しないものとする。

### 過去ログからの参照入力（エリア名・ダイビングポイント名）
- REQ-8.1: システムは、入力フォームのエリア名およびダイビングポイント名の各入力欄に、過去ログの入力値一覧を開く「参照」操作を併設するものとする。
- REQ-8.2: システムは、参照操作の有無にかかわらず、両項目への自由記述の直接入力を常に許可するものとする（参照は補助手段であり、入力を候補に限定しない）。
- REQ-8.3: ユーザーが参照操作を選択したとき、システムは保存済みの全ログから当該項目の値を集め、空文字および空白のみの値を除外し、重複を排除した候補一覧を表示するものとする。
- REQ-8.4: システムは、重複排除を前後の空白を除去した文字列の完全一致のみで行うものとする（大文字小文字・全角半角・送り仮名などの表記ゆれの正規化・名寄せは行わない）。
- REQ-8.5: システムは、候補一覧を「その値を使用したログの日付が新しい順」に並べるものとする（同一日付の場合は更新日時の新しい順）。
- REQ-8.6: ユーザーが候補を1件選択したとき、システムはその値を対応する入力欄に設定し、候補一覧を閉じるものとする（入力欄に既存の値があれば上書きする）。
- REQ-8.7: 候補が0件のとき、システムは参照操作を選択できない状態（無効表示）にするものとする。
- REQ-8.8: ユーザーが候補一覧を閉じる操作（キャンセル）を行ったとき、システムは入力欄の値を変更しないものとする。
- REQ-8.9: システムは、候補一覧の項目を編集・削除・追加する機能を提供しないものとする（候補は保存済みログから都度導出する派生データであり、マスタとして永続化しない）。
- REQ-8.10: システムは、ダイビングポイント名の候補一覧を、その時点でエリア名入力欄に入力されている値（前後空白を除去した文字列）で絞り込むものとする。エリア名が入力されているときはそのエリア名と完全一致するログのみからダイビングポイント名を集め、エリア名が未入力のときは全ログから集める（絞り込まない）。
- REQ-8.11: ユーザーが参照操作で選択した値は、システムは保存時に他の自由記述入力と区別せず、同じ文字列項目として保存するものとする（参照元ログへの参照や外部キーは保持しない）。
- REQ-8.12: エリア名の候補一覧は、ダイビングポイント名側の絞り込み（REQ-8.10）の影響を受けず、常に全ログから集めるものとする（一方向の絞り込みであり、ダイビングポイント名を選んでもエリア名候補は変化しない）。
- REQ-8.13: ユーザーが参照操作でダイビングポイント名の候補一覧を開いた後、パネルを閉じずにエリア名入力欄の値を変更したとき、システムはダイビングポイント名の候補一覧を新しいエリア名の値で再計算するものとする。

## 確定した判断ポイント（ユーザー確認済み）

以下はユーザーへの確認により確定した。以前の版にあった「未確定事項」はすべて解消済み。

1. **選択リストの選択肢**: 「器材の選択肢（プリセット）」の内容（ドライスーツをインナー厚みで区分、ウェットスーツを厚み+タイプ、タンクを容量で区分）はこのまま確定。
2. **引き継ぎ対象項目の範囲**: REQ-7.4 のとおり、装備系＋エリア名＋ガイド名＋バディ名のみとする（環境情報・ダイビングポイント名などの実測/その日固有の値は対象外）。
3. **引き継ぎ元の選び方**: REQ-7.3 のとおり、更新日時 (updatedAt) が最も新しいログを引き継ぎ元とする。
4. **日付変更時の再引き継ぎ**: REQ-7.10〜REQ-7.12 のとおり、自動では再引き継ぎせず、器材・エア管理セクションの手動ボタンで明示的に引き継ぐ。
5. **参照候補の並び順**: REQ-8.5 のとおり「最近潜った順」（頻度順ではない）とする。
6. **スーツ／タンクの排他性**: REQ-6.6, REQ-6.7 のとおり同時選択を許可する（排他制御・警告・自動クリアは行わない）。
7. **エリア名によるダイビングポイント名候補の絞り込み**: REQ-8.10, REQ-8.12, REQ-8.13 のとおり、ダイビングポイント名の参照候補はエリア名入力欄の現在値で絞り込む（一方向。ダイビングポイント名側からエリア名候補を絞り込むことはしない）。
