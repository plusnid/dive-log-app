# 要件: サイン入力の全画面化

関連: [設計](./design.md) / [概要](../00-overview.md) / [ガイドサインの記録](../guide-signature/requirements.md) / [写真の拡大表示](../photo-lightbox/requirements.md) / [iOS/Android動作保証](../mobile-compatibility/requirements.md) / [ダイビングログCRUD](../dive-log-crud/requirements.md) / [UI仕上げ レベル1](../ui-polish-level1/requirements.md) / [UI仕上げ レベル2](../ui-polish-level2/requirements.md) / [UI仕上げ レベル3](../ui-polish-level3/requirements.md)

ステータス: 実装済み（[未確定事項](#未確定事項確認したい点) 1〜9 はすべてユーザー確定済み、2026-08-10。いずれも推奨案どおり）

## 概要

現状、ガイドのサインは入力フォーム（`src/views/DiveLogFormView.tsx`）の「ガイドのサイン」欄に埋め込まれた**高さ160 CSSピクセル**の描画キャンバス（`src/components/SignaturePad.tsx` / `.css`）へ直接描く（[guide-signature REQ-2](../guide-signature/requirements.md)）。フォームの一部として縦に積まれているため描画領域が小さく、船上でガイドに端末を手渡して署名してもらう場面には不足している。

本仕様は、**サインの入力（描画）を画面いっぱいのモーダルで行えるようにする**ことを扱う。

本仕様は [photo-lightbox](../photo-lightbox/requirements.md) に続く、このアプリで2つ目のモーダル型オーバーレイである。photo-lightbox が**閲覧専用のビューア**であるのに対し、本仕様は**ポインタ操作による入力（canvasへの手書き）**を扱う点で性質が異なり、次の3点が新たな検討対象になる。

| # | photo-lightbox で扱わなかった論点 | 理由 |
| --- | --- | --- |
| 1 | オーバーレイ内でのポインタイベント処理（`setPointerCapture`・座標計算・`touch-action`） | ライトボックスは画像を表示するだけでポインタ処理を持たない |
| 2 | 閉じる操作が「入力内容の確定／破棄」を意味すること（Escape・OSの戻る操作を含む） | ライトボックスは閉じてもデータが変わらない（[photo-lightbox REQ-5.7](../photo-lightbox/requirements.md)） |
| 3 | 描画領域の縦横比と、そこから書き出される画像の縦横比 | ライトボックスは既存画像を表示するだけ |

保存されるデータの形式（`attachments` テーブルの `type: 'signature'` なPNG、`DiveLog.signatureId`。[guide-signature/design.md](../guide-signature/design.md)）は変更しない。

| サイン欄 | `src/components/SignaturePad.tsx` / `.css` | フォーム内の欄の役割の見直し（起動と現在の状態の提示）、フォームへの受け渡し |

### 対象外（今回やらないこと）

- **保存データの形式・Dexieスキーマ・[Google Drive同期](../google-drive-sync/requirements.md)の形式の変更**。サインは引き続き `attachments` の `type: 'signature'` なPNGとして1件保存する。
- **サイン画像の閲覧用の拡大表示**（詳細画面のサインをタップして拡大する機能）。[photo-lightbox REQ-1.8](../photo-lightbox/requirements.md) で対象外と確定済みであり、本仕様でも扱わない（本仕様は**入力**のみ）。
- **取り消し（Undo）／やり直し（Redo）／線の太さ・色の選択／消しゴム**。消去は現状どおり全消去（クリア）のみとする。
- **サインの複数保存**（1ログ1サインの制約は維持する。[guide-signature/design.md](../guide-signature/design.md)）。
- **ガイド名テキスト入力の全画面への移設**。ガイド名はフォーム内の入力欄のままとする（ソフトウェアキーボードとモーダルの高さ計算が絡み、[mobile-compatibility REQ-6.6](../mobile-compatibility/requirements.md) の考慮が増えるため）。
- **サイン以外の入力（写真・観察記録・メモ）の全画面化**。
- **削除確認（`window.confirm`）のモーダル化・汎用モーダル部品への一般化**（[photo-lightbox](../photo-lightbox/requirements.md) と同じ方針を維持する）。
- **ブラウザ履歴API（`pushState` / `popstate`）との統合**（[marine-life-observation REQ-11.19](../marine-life-observation/requirements.md) の方針を維持する。→ [11節](#11-画面遷移の履歴osの戻る操作との関係)）。
- **画面遷移アニメーション・フェードイン等の演出**。
- **依存パッケージの追加**（署名ライブラリ・モーダルライブラリ等）。

## 用語

- **サイン欄**: 入力フォームの「ガイドのサイン」fieldset 内に表示される、サインの現在の状態を示す領域（現状の `SignaturePad` が占める部分）。
- **全画面サイン入力**: 本仕様が追加する、画面全体を覆うモーダル。以下「サインモーダル」と呼ぶ。
- **描画領域**: サインモーダルの中でストロークを受け付ける矩形（`<canvas>`）。
- **確定**: サインモーダルで描いた内容を、フォームが保持するサインの状態へ反映すること。**この時点ではデータベースへ書き込まない**（書き込みはフォームの「保存」時。[guide-signature REQ-6](../guide-signature/requirements.md)）。
- **破棄**: サインモーダルを開く前のサインの状態に戻すこと。
- **未描画**: サインモーダルを開いてから一度もストロークが引かれていない、またはクリア後にストロークが引かれていない状態。

## 要件（EARS形式）

### 1. サインモーダルを開く

- REQ-1.1: システムは、入力フォーム（新規作成・編集の双方）のサイン欄から、サインモーダルを開く操作を提供するものとする（→ [未確定事項](#未確定事項確認したい点) 2）。
- REQ-1.2: システムは、サインモーダルを開く操作を、ポインタ操作（タップ・クリック）とキーボード操作（Tabでの到達、Enter または Space での実行）の双方で実行できるものとする。
- REQ-1.3: システムは、開く操作要素のタップ領域を最小44×44 CSSピクセル以上とするものとする（[mobile-compatibility REQ-6.3](../mobile-compatibility/requirements.md)）。
- REQ-1.4: システムは、同時に開くことができるサインモーダルを1つまでとするものとする。
- REQ-1.5: 対象ログに保存済みのサインが存在する状態で編集フォームを開いたとき、システムはサイン欄に既存のサイン画像を静止画として表示するものとする（[guide-signature REQ-4](../guide-signature/requirements.md) を維持する）。
- REQ-1.6: 保存済みサインが表示されている状態でユーザーが「サインをやり直す」に相当する操作を選択したとき、システムはサインモーダルを未描画の状態で開くものとする（[guide-signature REQ-5](../guide-signature/requirements.md) の描画開始手段を、埋め込みキャンバスからサインモーダルへ置き換える）。
- REQ-1.7: システムは、サインモーダルを開く操作によってデータベースを読み書きしないものとする。

### 2. サインモーダルの構成

- REQ-2.1: システムは、サインモーダルを画面全体（ビューポート全域）を覆う領域として表示するものとする。
- REQ-2.2: システムは、サインモーダルに次の要素を配置するものとする。
  - 描画領域（REQ-3.x）
  - サインモーダルであることが分かる見出し（例:「ガイドのサイン」）
  - 描画内容を全消去する操作（「クリア」）
  - サインモーダルを閉じる操作（REQ-4.x）
- REQ-2.3: システムは、描画領域を、現状のサイン欄（画面幅×160 CSSピクセル）より明確に大きい面積で提供するものとする（→ [未確定事項](#未確定事項確認したい点) 4）。
- REQ-2.4: サインモーダルを開いている間、システムは背後の入力フォームの操作要素を操作できない状態にするものとする（背後のボタン・入力欄がポインタ操作・キーボード操作のいずれでも作動しないものとする）。
- REQ-2.5: サインモーダルを開いている間、システムは背後のページをスクロールさせないものとする。
- REQ-2.6: システムは、サインモーダルの操作要素および描画領域が、ノッチ・ホームインジケーター等のセーフエリアに隠れない位置に配置されるものとする（[mobile-compatibility REQ-6.1](../mobile-compatibility/requirements.md)）。
- REQ-2.7: システムは、サインモーダルに写真・観察記録・ガイド名等、サイン以外の入力要素を含めないものとする。
- REQ-2.8: システムは、サインモーダル内の操作要素のタップ領域を最小44×44 CSSピクセル以上とするものとする（[mobile-compatibility REQ-5.6](../mobile-compatibility/requirements.md)）。

### 3. 描画

- REQ-3.1: システムは、描画領域上のポインター操作（マウス／タッチ／ペン）による連続的なストロークをサインとして描画するものとする（[guide-signature REQ-2](../guide-signature/requirements.md)、[mobile-compatibility REQ-5.1](../mobile-compatibility/requirements.md)）。
- REQ-3.2: ユーザーが描画領域上で指を動かしているとき、システムはページのスクロール・ピンチズーム・引っ張って更新（pull-to-refresh）を発生させないものとする（[mobile-compatibility REQ-5.2](../mobile-compatibility/requirements.md)）。
- REQ-3.3: ユーザーが描画領域を長押ししたとき、システムはテキスト選択メニューや画像保存メニュー等のOS標準メニューを表示しないものとする（[mobile-compatibility REQ-5.3](../mobile-compatibility/requirements.md)）。
- REQ-3.4: システムは、ストロークの開始点が描画領域内である限り、指が描画領域の外へ出て戻る操作を1本の連続したストロークとして扱うものとする。
- REQ-3.5: システムは、端末のピクセル密度（`devicePixelRatio`）にかかわらず、線が滲まない解像度でサインを描画・書き出しするものとする（[mobile-compatibility REQ-5.4](../mobile-compatibility/requirements.md)。ただし書き出し解像度の上限は → [未確定事項](#未確定事項確認したい点) 8）。
- REQ-3.6: ユーザーが「クリア」を選択したとき、システムは描画領域の内容をすべて消去し、未描画の状態に戻すものとする（[guide-signature REQ-3](../guide-signature/requirements.md)）。
- REQ-3.7: サインモーダルを開いている間に画面の向きが変わった、または描画領域の表示サイズが変化したとき、システムは描画済みのストロークを保持するものとする。このとき、システムはストロークの縦横比を崩さないものとする（[mobile-compatibility REQ-5.5](../mobile-compatibility/requirements.md) の具体化）。
- REQ-3.8: システムは、描画領域の背景をOSのテーマ設定（ライト／ダーク）によらず白、線を濃い色とするものとする（[mobile-compatibility REQ-6.5](../mobile-compatibility/requirements.md) の「白背景を前提とする描画領域は除く」に従う）。
- REQ-3.9: システムは、描画領域が未描画である間、そこがサインを描く領域であることが分かる表示（プレースホルダー等）を行うものとする。当該表示は書き出される画像に含めないものとする。

### 4. 確定・閉じる操作

> 本節の分岐は [未確定事項](#未確定事項確認したい点) 5 の決定に依存する。以下は方式によらず満たすべき事項を記す。

- REQ-4.1: システムは、サインモーダル内に閉じる操作要素を常時表示するものとする。
- REQ-4.2: ユーザーが Escape キーを押したとき、システムはサインモーダルを閉じるものとする。
- REQ-4.3: システムは、Escape キー・OSの戻る操作・その他ユーザーの明示的な確定操作を経ない閉じ方によって、ユーザーが描いたストロークを**予告なく失わせない**ものとする（→ [未確定事項](#未確定事項確認したい点) 5）。
- REQ-4.4: システムは、描画領域上のポインタ操作によってサインモーダルを閉じないものとする。
- REQ-4.5: サインモーダルを確定して閉じたとき、システムは描画内容をPNG画像としてフォームが保持するサインの状態へ反映し、サイン欄にその内容を表示するものとする。
- REQ-4.6: サインモーダルを閉じたとき、システムはフォーカスをサインモーダルを開いた操作要素へ戻すものとする（フォーカスが `body` へ外れる状態を発生させないものとする。[photo-lightbox REQ-5.5](../photo-lightbox/requirements.md)、`AppMenu` の閉じる処理と同じ方針）。
- REQ-4.7: サインモーダルを閉じたとき、システムは入力フォームの入力途中の内容とスクロール位置を、開く前と同じ状態に保つものとする。
- REQ-4.8: システムは、サインモーダルの開閉によってデータベースを更新しないものとする（データベースへの反映はフォームの「保存」時に限るものとする。REQ-5.x）。
- REQ-4.9: 未描画のままサインモーダルを閉じたとき、システムは [未確定事項](#未確定事項確認したい点) 6 の決定に従ってサインの状態を決めるものとし、既存のサインが失われる場合はその旨がユーザーに分かる状態にするものとする。

### 5. フォームおよび保存との関係

- REQ-5.1: システムは、フォーム送信時のサインの扱いを [guide-signature REQ-6](../guide-signature/requirements.md) の3分岐（未編集は変更なし／未サインは削除／新規描画は置き換え）と等価に保つものとする（→ ただし「未描画で閉じた場合」の解釈は [未確定事項](#未確定事項確認したい点) 6）。
- REQ-5.2: システムは、サインモーダルで確定した内容を、フォームを送信するまでデータベースに書き込まないものとする。
- REQ-5.3: ユーザーがサインモーダルを確定した後にフォームの入力を続けたとき、システムは確定済みのサインを保持するものとする。
- REQ-5.4: ユーザーがサインモーダルを確定した後に再度サインモーダルを開いたとき、システムは直前に確定したサインを描画済みの状態として表示し、続きから編集できるものとする（→ [未確定事項](#未確定事項確認したい点) 3。方式によっては「未描画で開き、確定すると上書き」となるため、その場合は本要件を採らない）。
- REQ-5.5: ユーザーがフォームを送信せずに画面を離れたとき、システムは確定済みのサインを保存しないものとする（現状の挙動を変更しない）。
- REQ-5.6: システムは、サイン欄に現在のサインの状態（未サイン／既存サインあり／新しく描いたサインあり）が視覚的に区別できる表示を行うものとする。
- REQ-5.7: システムは、既存のサインを明示的に削除して「未サイン」に戻す手段を提供するものとする（→ [未確定事項](#未確定事項確認したい点) 6）。

### 6. 表示・配色・レイアウト

- REQ-6.1: システムは、サインモーダルの面（背景・ヘッダー・操作要素）に既存の配色トークン（`--surface` / `--text` / `--border` / `--accent` 等。[ui-polish-level2](../ui-polish-level2/requirements.md)）を用いるものとする。ただし描画領域そのものは REQ-3.8 に従い白固定とする。
- REQ-6.2: システムは、サインモーダル内のテキストと背景のコントラスト比を4.5:1以上、アイコン・境界などの非テキスト要素を3:1以上に保つものとする（[mobile-compatibility REQ-6.5](../mobile-compatibility/requirements.md)、[ui-polish-level1 REQ-5.4](../ui-polish-level1/requirements.md)）。
- REQ-6.3: システムは、本機能で追加するピクトグラムを既存のアイコン方式（インラインSVG・単色・文字色追従・支援技術から除外）で実装するものとする（[ui-polish-level1 REQ-3.2〜REQ-3.5](../ui-polish-level1/requirements.md)）。外部のアイコンライブラリ・Webフォント・外部ホストの画像を導入しないものとする。
- REQ-6.4: システムは、ピクトグラムのみで操作の意味を伝えないものとする（テキストによる名前を併用するものとする。[ui-polish-level1 REQ-3.6](../ui-polish-level1/requirements.md)）。
- REQ-6.5: システムは、幅320 CSSピクセル以上の縦向き画面において、サインモーダルが横スクロールを発生させないものとする（[mobile-compatibility REQ-6.4](../mobile-compatibility/requirements.md)）。
- REQ-6.6: システムは、サインモーダルの開閉にアニメーション演出を行わないものとする（`prefers-reduced-motion` への分岐を必要としない実装とするものとする）。
- REQ-6.7: システムは、サインモーダルの導入によって、詳細画面（`.detail-signature`）および一覧のサイン有無表示（[ui-polish-level1](../ui-polish-level1/requirements.md) の `SignedIcon`）のレイアウトを破綻させないものとする。保存される画像の縦横比が可変になる場合は、表示側で縦横比を保ったまま収める指定を行うものとする（→ [未確定事項](#未確定事項確認したい点) 4）。

### 7. アクセシビリティ

- REQ-7.1: システムは、サインモーダルをモーダルダイアログとして支援技術に伝えるものとする（ダイアログであること、および背後の内容が操作対象外であることが伝わるものとする）。
- REQ-7.2: サインモーダルを開いたとき、システムはフォーカスをサインモーダルの内部へ移すものとする。
- REQ-7.3: サインモーダルを開いている間、システムはキーボードのフォーカスをサインモーダルの内部に留めるものとする（Tab の連続操作で背後の要素へ到達しないものとする）。
- REQ-7.4: システムは、サインモーダル自体にアクセシブルな名前（例:「ガイドのサインを入力」）を与えるものとする。
- REQ-7.5: システムは、サインモーダル内のすべての操作要素（クリア・確定・閉じる）に、テキストによるアクセシブルな名前を与え、キーボードのみで実行可能にするものとする。
- REQ-7.6: システムは、サインモーダルを開く操作要素のアクセシブルな名前を、操作の結果（サインを入力する画面が開くこと）が分かる文言とするものとする。
- REQ-7.7: システムは、描画領域に、そこが手書き入力の領域であることを説明するテキストを支援技術へ提供するものとする。
- REQ-7.8: システムは、手書きによる描画そのものをキーボード操作の代替手段で提供しないものとする（canvasへの手書きは本質的にポインタ操作を要するため）。ただし、システムは**サインを入力せずにフォームを保存する経路**（サインは任意項目。[guide-signature REQ-1](../guide-signature/requirements.md)）と、**サインモーダルを開いてしまった場合に安全に閉じる経路**を、キーボード操作のみで確保するものとする。
- REQ-7.9: システムは、サインモーダル内の操作要素について、キーボードフォーカスの位置が視覚的に判別できる状態を保つものとする。
- REQ-7.10: システムは、サインモーダルの表示中に、ブラウザ・OSが提供するピンチズームを新たに禁止しないものとする（`user-scalable=no` 等の指定を追加しないものとする。[photo-lightbox REQ-7.10](../photo-lightbox/requirements.md)）。ただし描画領域上のジェスチャーは REQ-3.2 に従う。

### 8. 非機能・回帰防止

- REQ-8.1: システムは、本機能の実装のために依存パッケージ（署名・モーダル・フォーカストラップ等のライブラリ）を新規に追加しないものとする。
- REQ-8.2: システムは、サインモーダルをオフラインで動作可能とするものとする（[概要 NFR-1, NFR-2](../00-overview.md)、[mobile-compatibility REQ-3.1](../mobile-compatibility/requirements.md)）。
- REQ-8.3: システムは、本機能の追加によって保存されるデータ・Dexieのスキーマ・[Google Drive同期](../google-drive-sync/requirements.md)の形式・`schemaVersion` を変更しないものとする。
- REQ-8.4: システムは、本機能の追加によって [guide-signature](../guide-signature/requirements.md) の保存フロー（`createDiveLog` / `updateDiveLog` に渡す `Blob | null | undefined` の三値の意味）を変更しないものとする。
- REQ-8.5: システムは、UIコンポーネントから Dexie を直接操作せず、リポジトリ関数を経由する既存の依存の向き（[概要のアーキテクチャ概要](../00-overview.md)）を維持するものとする。
- REQ-8.6: システムは、サインモーダルの開閉を繰り返しても、解放されないオブジェクトURL・登録されたままのイベントリスナー・`ResizeObserver` が残らないものとする。
- REQ-8.7: サインモーダルに必要なブラウザ機能が利用できない環境において、システムは代替として現状と同等のサイン入力手段（フォーム内の描画キャンバス）を提供するか、少なくともサインを入力できない状態でフォームの他の項目の入力・保存を継続可能にするものとする（機能検出により分岐し、エラーを発生させないものとする。[mobile-compatibility REQ-1.2, REQ-1.3](../mobile-compatibility/requirements.md)。→ [未確定事項](#未確定事項確認したい点) 1）。
- REQ-8.8: システムは、書き出すサイン画像の形式を PNG（`image/png`）のまま維持するものとする。
- REQ-8.9: システムは、本仕様およびコードに、公開リポジトリで問題となる個人情報を含めないものとする。特に、**実在するガイドの氏名・サイン画像をドキュメント・スクリーンショット・テストデータとして含めないものとする**。

### 9. 履歴・画面遷移との関係

- REQ-9.1: システムは、サインモーダルの開閉を `src/App.tsx` の画面遷移履歴（[marine-life-observation REQ-11.1](../marine-life-observation/requirements.md)）のエントリとして積まないものとする（→ [未確定事項](#未確定事項確認したい点) 9）。
- REQ-9.2: 入力フォームから他の画面へ遷移したとき、システムはサインモーダルを残さないものとする。
- REQ-9.3: システムは、サインモーダルを開いている間、背面のフォームの「キャンセル」「保存」を含む操作を実行できない状態に保つものとする（REQ-2.4）。
- REQ-9.4: システムは、サインモーダルの状態を再読み込み（リロード）をまたいで保持しないものとする。
- REQ-9.5: システムは、[marine-life-observation REQ-11.19](../marine-life-observation/requirements.md) の方針（アプリ内部の遷移履歴はブラウザ／OSの戻る操作と連動しない）を変更しないものとする。ただし、ブラウザが標準の挙動としてOSの戻る操作を「開いているモーダルを閉じる」操作に割り当てる場合、システムはこれを妨げないものとする（このときの入力内容の扱いは REQ-4.3 に従う）。

## 未確定事項（確認したい点）

すべてユーザー確定済み（2026-08-10）。いずれも推奨案どおりに確定した。各項目の比較・根拠は [設計](./design.md) の該当節を参照。

1. **実装方式**: **確定＝ネイティブ `<dialog>` + `showModal()`**（[photo-lightbox](../photo-lightbox/design.md) と同じ方式）。`<dialog>` 非対応環境では現状の埋め込みキャンバスにフォールバックする（REQ-8.7）。

2. **サインモーダルを開く操作**: **確定＝サイン欄を「現在の状態のプレビュー＋『サインを入力する』ボタン」に変更し、ボタンからのみ開く**。サイン欄では描画しない。

3. **既存 `SignaturePad` との関係・描画キャンバスの数**: **確定＝描画するcanvasはサインモーダル内の1つだけにする**。`SignaturePad` は「状態の提示＋起動＋フォームへの受け渡し」に役割を変える。**デスクトップで「小さい欄にマウスで直接描く」ことはできなくなる**（必ずモーダルを開く）ことを許容する。一度確定したサインを開き直したときは、確定済みPNGをモーダル内canvasへ描画して続きから編集できるようにする（REQ-5.4）。

4. **描画領域の形（縦横比）**: **確定＝ヘッダーを除くビューポート全体を描画領域にする**。縦向きでは縦長、横向きでは横長になる（面積は現状の約4倍）。保存される画像の縦横比が可変になるため、詳細画面（`.detail-signature`）に `max-height` と `object-fit: contain` を追加する（REQ-6.7）。

5. **閉じる操作の意味（確定／破棄）と Escape の扱い**: **確定＝オートコミット**。閉じる操作は常に「確定して閉じる」。ボタンは「完了」（primary）と「クリア」の2つ。Escape・OSの戻る操作・背景タップも「完了」と同じ扱いにする。破棄したい場合は「クリア」してから閉じる。

6. **既存サインの削除手段と「未描画で閉じたとき」の扱い**: **確定＝「未描画で閉じたら既存サインを維持する」に変更し、削除は専用の「サインを削除」ボタンで明示的に行う**。[guide-signature REQ-6](../guide-signature/requirements.md) の記述の更新が必要（実装時に反映する）。

7. **フォームへのデータの受け渡し**: **確定＝既存の `SignaturePadHandle.exportBlob()` の三値契約（`undefined` / `null` / `Blob`）を維持する**。`SignaturePad` が内部に確定済みの状態を持ち、`DiveLogFormView` は無変更。

8. **書き出し解像度の上限**: **確定＝上限を設けない**（描画領域のCSSサイズ×dpr をそのまま書き出す）。

9. **画面遷移の履歴スタックとの関係**: **確定＝`SignaturePad`（またはフォーム）のローカル state だけで完結させ、`src/App.tsx` の履歴スタックには載せない**（[photo-lightbox REQ-6.1](../photo-lightbox/requirements.md) と同じ方針）。
