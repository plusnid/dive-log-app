# 要件: iOS / Android での動作保証（モバイル対応）

関連: [設計](./design.md) / [概要](../00-overview.md) / [オフライン・PWA](../offline-pwa/requirements.md) / [写真添付](../photo-attachment/requirements.md) / [ガイドサイン](../guide-signature/requirements.md) / [UI仕上げ レベル3](../ui-polish-level3/requirements.md)

ステータス: 実装済み（対応を保留した項目は「対象外」節および [設計](./design.md) の「既知の制約・リスク」を参照。動作確認マトリクス（REQ-7、[設計](./design.md#動作確認マトリクスreq-7)）の実機検証は別途実施）
※ REQ-2.3 の例外として追記した「メニューからの明示的な再表示」は [ui-polish-level3](../ui-polish-level3/requirements.md) で仕様化しており、同仕様の実装をもって満たされる（本仕様側の実装変更は `InstallGuide` への任意prop追加のみ）。

## 概要

本アプリはネイティブアプリ化（Capacitor 等でのストア配布）を行わず、**Web/PWA のまま** iOS Safari と Android Chrome の両方で実用に耐えることを目標とする。
[offline-pwa](../offline-pwa/requirements.md) が「PWA という技術基盤（Service Worker / Manifest）」を扱うのに対し、本仕様は「**サポート対象プラットフォーム上で、各機能が実際に動作することの保証**」を扱う。

主要な利用シーンは NFR-3 のとおりスマートフォンであり、ダイビング直後の船上・ビーチ（＝電波が不安定、手が濡れている、直射日光下）での入力を想定する。

## サポート対象プラットフォーム

| 区分 | プラットフォーム | ブラウザ | 位置づけ |
| --- | --- | --- | --- |
| Tier 1 | iOS / iPadOS 16.4 以降 | Safari（ホーム画面追加を推奨） | 全機能を保証 |
| Tier 1 | Android 10 以降 | Chrome 最新安定版およびその1つ前 | 全機能を保証 |
| Tier 2 | デスクトップ | Chrome / Edge / Safari 最新版 | 動作するが最適化対象外 |
| 対象外 | - | iOS 上の Chrome / Firefox / Edge（WebKit ベース） | Safari と同等に動くことを期待するが保証しない |
| 対象外 | - | Android WebView 内蔵ブラウザ、その他ブラウザ | 保証しない |

## 用語

- **インストール**: ホーム画面へのアプリ追加（Add to Home Screen / A2HS）。
- **スタンドアロン起動**: インストールしたアイコンから、ブラウザUIなしで起動した状態（`display: standalone`）。
- **ブラウザタブ起動**: インストールせずブラウザのタブで開いた状態。

## 要件（EARS形式）

### 1. プラットフォーム対応の明示

- REQ-1.1: システムは、上記「サポート対象プラットフォーム」の Tier 1 に該当する環境において、ダイビングログの記録・閲覧・編集・削除、写真添付、ガイドサイン記録、オフライン動作のすべてを利用可能にするものとする。
- REQ-1.2: システムは、サポート対象外のブラウザで動作を保証しないが、機能を意図的に制限したりブロックしたりしないものとする。
- REQ-1.3: システムは、プラットフォーム固有の分岐が必要な箇所において、ユーザーエージェント文字列ではなく機能検出（feature detection）を用いて分岐するものとする。ただし、インストール手順の案内文言などユーザーエージェントでしか判別できない表示に限り、プラットフォーム判定を用いてよいものとする。

### 2. インストール（ホーム画面追加）

- REQ-2.1: Android Chrome でインストール要件が満たされたとき、システムはブラウザ標準のインストール導線（インストールバナー／メニュー）を利用可能にするものとする。
- REQ-2.2: ユーザーがブラウザタブでアプリを開いており、かつ未インストールのとき、システムは実行中のプラットフォームに応じたインストール手順の案内を表示するものとする（iOS: 共有メニュー →「ホーム画面に追加」、Android: メニュー →「アプリをインストール」）。
- REQ-2.3: ユーザーが案内を閉じたとき、システムはその選択を記憶し、同一ブラウザでは再表示しないものとする。ただし、ユーザーがメニューから明示的に再表示を求めた場合は再表示してよいものとし（[ui-polish-level3 REQ-2.16〜REQ-2.24](../ui-polish-level3/requirements.md)）、再表示後に改めて閉じたときは本要件のとおり再び記憶するものとする。
- REQ-2.4: アプリがスタンドアロン起動されているとき、システムはインストール案内を表示しないものとする。
- REQ-2.5: システムは、iOS のホーム画面アイコンとして正しく表示されるアイコン（`apple-touch-icon`）と、Android のアダプティブアイコンに対応するマスカブルアイコンの双方を提供するものとする（[offline-pwa REQ-5](../offline-pwa/requirements.md) の具体化）。
- REQ-2.6: インストール済みアプリが起動されたとき、システムはブラウザUIを表示しないスタンドアロン表示で起動するものとする（[offline-pwa REQ-3](../offline-pwa/requirements.md)）。

### 3. オフライン動作とデータ永続性

- REQ-3.1: システムは、Tier 1 の各プラットフォームにおいて、機内モード等でネットワークが完全に遮断された状態でも、一覧・詳細・新規作成・編集・削除・写真添付・サイン描画のすべてを実行可能にするものとする。
- REQ-3.2: システムは、初回起動時にストレージ永続化（`navigator.storage.persist()`）を要求し、ブラウザによる自動的なデータ削除の対象になりにくくするものとする。
- REQ-3.3: ストレージ永続化APIが利用できない、または永続化が許可されなかった場合、システムはエラーとして扱わず通常どおり動作を継続するものとする。
- REQ-3.4: システムは、ユーザーが確認できる場所（設定/情報画面）に、ストレージ永続化の状態と推定使用量（`navigator.storage.estimate()` が利用可能な場合）を表示するものとする。
- REQ-3.5: iOS のブラウザタブ起動時にはブラウザのストレージ削除ポリシーによって保存データが失われる可能性があるため、システムは iOS のブラウザタブ利用時にホーム画面への追加を推奨する注意文を表示するものとする。
- REQ-3.6: iOS において、ブラウザタブで保存したデータとホーム画面Webアプリで保存したデータが共有されない可能性があるため、システムは REQ-2.2 の案内文にその旨（「追加前に入力した記録は引き継がれない場合があります」）を含めるものとする。
- REQ-3.7: 保存操作中にストレージ容量超過（`QuotaExceededError`）が発生したとき、システムは処理を中断し、容量不足である旨と対処（不要な写真の削除など）を日本語で通知するものとする。

### 4. 写真選択

写真の追加手段は「ライブラリ/ファイルから選択」のみとする（カメラでの直接撮影用UIは設けない）。詳細は [photo-attachment REQ-2](../photo-attachment/requirements.md)。

- REQ-4.1: システムは、写真の追加手段として「ライブラリ/ファイルから選択」を、Tier 1 の各プラットフォームで利用可能にするものとする。
- REQ-4.2: ユーザーがライブラリ/ファイルから写真を選択したとき、システムは複数枚の同時選択を可能にするものとする。
- REQ-4.3: 写真ライブラリへのアクセスがOS設定で拒否されている場合、システムはアプリをクラッシュさせず、写真が追加されなかったことをユーザーが理解できる状態を保つものとする。
- REQ-4.4: ユーザーが写真を選択した後にアプリがバックグラウンドから復帰したとき、システムは入力途中のフォーム内容と選択済み写真を失わないものとする。
- REQ-4.5: 選択された画像が実行中のブラウザで表示できない形式（例: 一部の HEIC/HEIF）であった場合、システムはサムネイル表示が行えない旨を通知し、他の写真の添付処理は継続するものとする。
- REQ-4.6: システムは、端末のカメラロールに保存された高解像度画像を添付できるものとし、1枚あたりのファイルサイズによって添付を拒否しないものとする（容量超過時の扱いは REQ-3.7 に従う）。

### 5. タッチ操作によるサイン描画

- REQ-5.1: システムは、iOS Safari および Android Chrome において、指またはスタイラスによる連続的なストロークをサインとして描画可能にするものとする。
- REQ-5.2: ユーザーがサインキャンバス上で指を動かしているとき、システムはページのスクロール・ピンチズーム・引っ張って更新（pull-to-refresh）を発生させないものとする。
- REQ-5.3: ユーザーがサインキャンバスを長押ししたとき、システムはテキスト選択メニューや画像保存メニュー等のOS標準メニューを表示しないものとする。
- REQ-5.4: システムは、端末のピクセル密度（`devicePixelRatio`）にかかわらず、線が滲まない解像度でサインを描画・保存するものとする。
- REQ-5.5: 描画中に画面の向きが変わった、または表示サイズが変化したとき、システムは描画済みのストロークを保持するか、失われる場合はその旨をユーザーが認識できる状態にするものとする。
- REQ-5.6: システムは、サインキャンバスおよびその操作ボタンを、片手のタッチ操作で扱える大きさ（タップ領域の最小44×44 CSSピクセル）で提供するものとする。

### 6. 画面表示・タッチ操作全般

- REQ-6.1: システムは、ノッチ／ホームインジケーター／ステータスバーのある端末において、UI要素がそれらに隠れないようセーフエリアを考慮したレイアウトを提供するものとする。
- REQ-6.2: システムは、数値入力欄に対して、端末のソフトウェアキーボードで小数点を含む数値を入力できる入力モードを指定するものとする。
- REQ-6.3: システムは、ボタン・リスト行などの操作要素のタップ領域を最小44×44 CSSピクセル以上とするものとする。
- REQ-6.4: システムは、幅320 CSSピクセル以上の縦向き画面において、横スクロールを発生させずに全画面を表示するものとする。
- REQ-6.5: システムは、OSのダークモード設定に追従して配色を切り替えるものとする（サイン描画キャンバスなど、白背景を前提とする描画領域は除く）。
- REQ-6.6: ソフトウェアキーボードが表示されたとき、システムは入力中の項目が隠れないようにするものとする。

> 入力欄タップ時の iOS Safari 自動ズーム（フォーカス時の拡大）は既知の課題として認識しているが、今回は対応を保留する（[既知の制約・リスク](./design.md#既知の制約リスク) 参照）。

### 7. 動作検証

- REQ-7.1: システムのリリース前に、[設計](./design.md) の「動作確認マトリクス」に定義された確認項目を Tier 1 の各プラットフォームの実機で実施するものとする。
- REQ-7.2: 動作確認は、スタンドアロン起動とブラウザタブ起動の両方の状態について実施するものとする。
- REQ-7.3: 動作確認は、オンライン状態および機内モード（完全オフライン）の両方について実施するものとする。

## 対象外（このバージョンでは扱わない）

- ネイティブアプリ化（Capacitor / React Native / ストア配布）
- プッシュ通知、バックグラウンド同期、位置情報の取得
- タブレット／横向き専用レイアウトの最適化（動作はするが専用の最適化はしない）
- 自動化されたクロスブラウザテスト（実機での手動確認とする）
- iOS スプラッシュスクリーン画像（`apple-touch-startup-image`）の提供
- カメラでの直接撮影用UI（写真の追加はライブラリ/ファイル選択のみとする。主要利用ブラウザが iOS/Android とも Chrome であるため、カメラボタンの必要性は低いと判断）
- 入力欄タップ時の iOS Safari 自動ズーム対策（原因は把握済みだが、今回は対応を保留。詳細は [設計](./design.md#既知の制約リスク)）
