# 要件: フローティング戻るボタン（スクロールしても消えない戻る導線）

関連: [設計](./design.md) / [概要](../00-overview.md) / [ダイビングログCRUD](../dive-log-crud/requirements.md) / [観察した生物の記録・検索](../marine-life-observation/requirements.md) / [UI仕上げ レベル1](../ui-polish-level1/requirements.md) / [UI仕上げ レベル3](../ui-polish-level3/requirements.md) / [写真の拡大表示](../photo-lightbox/requirements.md) / [サイン入力の全画面化](../signature-fullscreen/requirements.md) / [iOS/Android動作保証](../mobile-compatibility/requirements.md) / [Google Drive同期](../google-drive-sync/requirements.md)

ステータス: 実装済み（2026-08-15。[確定事項](#確定事項ユーザー確認済み) 1〜5 はすべてユーザー確定済み。3 のみ推奨案とは異なる結論＝**入力フォーム画面は対象外**。reviewerによる検査で仕様との乖離なしを確認済み）

## 概要

一覧画面（履歴の起点）以外のほぼすべての画面は、現在 `.view` コンテナの先頭にインラインの「← 戻る」ボタンを描いている。
このボタンは通常のフロー内にあるため、画面を下へスクロールすると視界から外れ、戻るには一度最上部までスクロールし直す必要がある。
本仕様は、この戻る導線を**スクロール位置によらず常に画面上に留まるフローティングボタン**へ置き換える。

対象は **詳細画面（`DiveLogDetailView`）・設定画面（`SyncSettingsView`）・生物検索画面（`CreatureSearchView`）の3画面**であり、
**入力フォーム画面（`DiveLogFormView`）は対象外**とする（現行のインラインの「← キャンセル」を据え置く。理由は [スコープ](#対象外今回やらないこと)）。

- 前例として、一覧画面には画面右下に固定表示されるFAB（[ui-polish-level3 REQ-1.1〜REQ-1.14](../ui-polish-level3/requirements.md)、`src/components/Fab.tsx`）があり、固定配置・セーフエリア対応・コンテンツ列への追従・アクセシブルな名前という慣習が確立している。本仕様はこの慣習を踏襲する。
- 本仕様は**表示層と操作要素の置き場所だけの変更**であり、戻る動作そのもの（`src/App.tsx` の `back()`）・履歴スタックの仕様（[marine-life-observation REQ-11](../marine-life-observation/requirements.md)）・保存されるデータには一切影響しない。

## スコープ

### 対象

| 対象 | ファイル（想定） | 内容 |
| --- | --- | --- |
| フローティング戻るボタンの共通部品 | `src/components/FloatingBackButton.tsx` / `.css`（新規） | 固定表示の戻るボタン本体 |
| 画面切り替え | `src/App.tsx` | 一覧以外の画面での戻るボタンの描画（→ [設計 5](./design.md#5-描画場所)） |
| 詳細画面 | `src/views/DiveLogDetailView.tsx` | インラインの「← 戻る」の撤去 |
| 設定画面 | `src/views/SyncSettingsView.tsx` | インラインの「← 戻る」の撤去、`.view__header` の整理 |
| 生物検索画面 | `src/views/CreatureSearchView.tsx` | インラインの「← 戻る」3箇所の撤去、`.view__header` の整理 |
| レイアウト | `src/App.css` | 固定ボタンと本文が重ならないための余白 |
| アイコン | `src/components/icons.tsx` | 既存の `ChevronLeftIcon` を再利用（新規追加は原則不要） |

### 対象外（今回やらないこと）

- **入力フォーム画面（`src/views/DiveLogFormView.tsx`）**。本機能の対象は詳細画面・設定画面・生物検索画面の3画面とし、入力フォーム画面は現行のインライン（テキスト付き）の「← キャンセル」ボタンのまま据え置く。**理由: 未保存の入力に対する確認ダイアログが現状存在せず（REQ-2.4）、常時表示のフローティングボタン化は誤タップによる入力喪失リスクを高めるため**（2026-08-15 ユーザー確定。[確定事項](#確定事項ユーザー確認済み) 3）。この結果、入力フォーム画面だけ戻る導線の見た目・位置が他画面と異なる状態になるが、これは意図した例外とする（REQ-3.6）。
- **入力フォーム画面の「読み込み中...」状態に戻る手段がない問題**（既存ログの編集時に一瞬表示される。→ [設計 1](./design.md#1-現状調査結果)）。同種の行き止まりのうち、本仕様で解消するのは対象3画面のものだけとする（REQ-3.5）。入力フォーム画面を対象外としたため、当該画面の行き止まりは残る（解消する場合は別途ユーザー確認のうえ、本仕様の改訂または別仕様として起票する）。
- **戻る動作そのものの変更**。1つ前の画面へ戻る／戻り先がなければ一覧、という挙動（[marine-life-observation REQ-11.2, REQ-11.3](../marine-life-observation/requirements.md)）は変更しない。
- **ブラウザ／OSの戻る操作（`history.pushState` / `popstate`）との統合**（[marine-life-observation REQ-11.19](../marine-life-observation/requirements.md) の方針を維持する）。
- **一覧画面への戻るボタンの追加**。一覧は履歴の起点であり戻り先が存在しない（[marine-life-observation REQ-11.3](../marine-life-observation/requirements.md)）。
- **FABの位置・見た目・対象画面の変更**（[ui-polish-level3 REQ-1](../ui-polish-level3/requirements.md) を維持する）。
- **未保存の入力がある状態で画面を離れるときの確認ダイアログの新設**（現状も確認は行っていない。入力フォーム画面を対象外とした前提でもあるため、本仕様では現行動作を維持する。REQ-2.4）。
- **各画面のヘッダーを共通レイアウト部品（AppBar 等）へ統合すること**。本仕様が追加するのは戻るボタン1つの部品に留める（→ [設計 2-4](./design.md#2-4-検討したが採らなかった方式)）。
- **スクロール方向に応じた自動的な表示／非表示（オートハイド）**、および画面遷移・ボタン出現のアニメーション（[ui-polish-level3](../ui-polish-level3/requirements.md) / [photo-lightbox REQ-8.5](../photo-lightbox/requirements.md) の演出を行わない方針を維持する）。
- **モーダル（[写真の拡大表示](../photo-lightbox/requirements.md)・[サイン入力](../signature-fullscreen/requirements.md)）の閉じる操作の変更**。モーダル内の閉じる導線は現状のまま。

## 用語

- **フローティング戻るボタン**: 画面のスクロールに追従せず一定位置に浮いて表示される、1つ前の画面へ戻るための操作要素。本仕様が追加する部品を指す。
- **インラインの戻るボタン**: 現在 `.view` の通常フロー先頭に置かれている「← 戻る」ボタン。本仕様で撤去する対象。
- **コンテンツ列**: `#root` の中央寄せ・最大幅640pxの表示領域（`src/index.css`）。
- **セーフエリア**: ノッチ・ホームインジケーター等に隠れない表示領域（`env(safe-area-inset-*)`。[mobile-compatibility REQ-6.1](../mobile-compatibility/requirements.md)）。
- **FAB**: 一覧画面の右下に固定表示される新規記録用の円形ボタン（[ui-polish-level3](../ui-polish-level3/requirements.md)、`src/components/Fab.tsx`）。
- **アクセシブルな名前**: 支援技術が操作要素を読み上げるときの名前（`aria-label` 等で与えるもの）。

## 要件（EARS形式）

### 1. フローティング戻るボタンの表示

- REQ-1.1: システムは、一覧画面以外の画面において、1つ前の画面へ戻る操作を、画面上の一定位置に固定表示されるボタンとして提供するものとする。
- REQ-1.2: ユーザーが画面をスクロールしているとき、システムはフローティング戻るボタンを画面上の同じ位置に表示し続けるものとする（スクロールに追従して画面外へ流れないものとする）。
- REQ-1.3: システムは、同一時点に表示するフローティング戻るボタンを1つまでとするものとする（画面内の状態が切り替わっても、常に1つだけ表示するものとする）。
- REQ-1.4: システムは、フローティング戻るボタンをコンテンツ列の左上に表示するものとし、一覧画面のFAB（画面右下、[ui-polish-level3 REQ-1.1](../ui-polish-level3/requirements.md)）と視覚的に重ならない位置とするものとする（[確定事項](#確定事項ユーザー確認済み) 1）。
- REQ-1.5: システムは、フローティング戻るボタンがノッチ・ホームインジケーター等のセーフエリアと重ならない位置に表示するものとする（[mobile-compatibility REQ-6.1](../mobile-compatibility/requirements.md)）。
- REQ-1.6: システムは、画面幅がコンテンツ列の最大幅（640px）を超える環境においても、フローティング戻るボタンを画面外に出さず、コンテンツ列との位置関係が破綻しない位置に表示するものとする（[ui-polish-level3 REQ-1.13](../ui-polish-level3/requirements.md) と同じ考え方とする）。
- REQ-1.7: システムは、フローティング戻るボタンのタップ領域を最小44×44 CSSピクセル以上とするものとする（[mobile-compatibility REQ-6.3](../mobile-compatibility/requirements.md)）。
- REQ-1.8: システムは、フローティング戻るボタンを不透明な背景で表示し、背後の本文が透けて読み取りづらくならない状態にするものとする。
- REQ-1.9: システムは、フローティング戻るボタンが本文コンテンツより前面に表示される重なり順とし、本文に隠れて操作できない状態を発生させないものとする。
- REQ-1.10: システムは、一覧画面（履歴の起点）においてフローティング戻るボタンを表示しないものとする（[marine-life-observation REQ-11.3](../marine-life-observation/requirements.md)）。
- REQ-1.11: システムは、フローティング戻るボタンの表示・非表示をスクロール方向・スクロール量によって切り替えないものとする（対象画面では常時表示するものとする）。
- REQ-1.12: システムは、フローティング戻るボタンの表示・非表示にアニメーション演出を行わないものとする（`prefers-reduced-motion` への分岐を必要としない実装とするものとする）。
- REQ-1.13: システムは、フローティング戻るボタンを、左向きのシェブロン（既存の `ChevronLeftIcon`）のみを表示する円形のボタンとして提供するものとし、表示テキストを持たないものとする（[確定事項](#確定事項ユーザー確認済み) 2）。操作の意味は REQ-5.1 のアクセシブルな名前で伝えるものとする。
- REQ-1.14: システムは、フローティング戻るボタンの寸法をFAB（56×56、[ui-polish-level3 REQ-1.6](../ui-polish-level3/requirements.md)）より大きくしないものとし、主要操作（FAB）との強弱が視覚的に分かる状態にするものとする（REQ-1.7 の44×44を下回らないものとする）。

### 2. 戻る操作の動作

- REQ-2.1: ユーザーがフローティング戻るボタンを操作したとき、システムは現行のインラインの戻るボタンと同一の動作を行うものとする（1つ前の画面へ戻り、戻り先がなければ一覧画面を表示する。[marine-life-observation REQ-11.2, REQ-11.3](../marine-life-observation/requirements.md)）。
- REQ-2.2: システムは、本変更によって画面遷移の履歴スタックの構造・エントリの積み方・畳み方（[marine-life-observation REQ-11.1〜REQ-11.14](../marine-life-observation/requirements.md)）を変更しないものとする。
- REQ-2.3: システムは、戻る操作によってダイビングログのデータを読み書きしないものとする。
- REQ-2.4: システムは、未保存の入力がある状態で画面を離れるときの確認ダイアログを、本仕様では新規に設けないものとする（現行動作を維持するものとする）。
- REQ-2.5: 生物検索画面の3つの表示状態（読み込み中・生物一覧・該当ログ一覧）のいずれにおいても、システムは同一の戻る動作を提供するものとする（現行の3箇所のインラインボタンはいずれも同じ `onBack` を呼んでいるため、動作を変更しないものとする）。
- REQ-2.6: システムは、生物検索画面の「生物一覧」への常設導線（[marine-life-observation REQ-11.17](../marine-life-observation/requirements.md)）を撤去・変更しないものとする。

### 3. 対象画面と既存ボタンの置き換え

- REQ-3.1: システムは、詳細画面のインラインの「← 戻る」ボタンを撤去し、フローティング戻るボタンに置き換えるものとする。
- REQ-3.2: システムは、設定画面のインラインの「← 戻る」ボタンを撤去し、フローティング戻るボタンに置き換えるものとする。
- REQ-3.3: システムは、生物検索画面のインラインの「← 戻る」ボタン（読み込み中・生物一覧・該当ログ一覧の3箇所）を撤去し、フローティング戻るボタンに置き換えるものとする。
- REQ-3.4: システムは、入力フォーム画面のインラインの「← キャンセル」ボタンを本機能の対象に含めないものとし、その位置・表示文言・動作を現行から変更しないものとする（[確定事項](#確定事項ユーザー確認済み) 3）。すなわち、入力フォーム画面にはフローティング戻るボタンを表示しないものとする。
- REQ-3.5: システムは、対象3画面において、データの読み込み中および対象の記録が見つからなかった状態でもフローティング戻るボタンを表示するものとする。現状、詳細画面の「読み込み中...」および「記録が見つかりませんでした。」には戻る手段が存在せず、ユーザーが行き止まりになるため、本仕様でこれを解消するものとする（生物検索画面の読み込み中には現状も戻るボタンがあり、置き換え後も維持するものとする）。入力フォーム画面の「読み込み中...」状態は本仕様のスコープ外とする（REQ-3.4）。
- REQ-3.6: システムは、置き換えの対象となる3画面のすべてで同一の部品・同一の見た目・同一の位置を用いるものとし、対象画面の間で戻る導線の見た目や置き場所が異なる状態を発生させないものとする。入力フォーム画面の「← キャンセル」だけが異なる見た目・位置になることは、REQ-3.4 に基づく意図した例外とする。
- REQ-3.7: システムは、本変更によって各画面の既存の操作要素（詳細画面の「編集」「削除」、生物検索画面の検索欄・絞り込み・「生物一覧」、入力フォーム画面の「← キャンセル」「保存」）の位置・文言・動作を変更しないものとする。
- REQ-3.8: システムは、本変更によって各画面の見出し（`h1`）・本文の表示内容および順序を変更しないものとする。

### 4. 既存レイアウトとの共存

- REQ-4.1: システムは、各画面を最上部まで表示している状態において、見出し（`h1`）およびその直下の本文がフローティング戻るボタンに覆われない状態にするものとする。
- REQ-4.2: システムは、画面を端までスクロールした状態において、当該端に位置する操作要素（詳細画面の「編集」「削除」等）がフローティング戻るボタンに覆われて操作できない状態にならないよう、十分な余白を確保するものとする（[ui-polish-level3 REQ-1.9](../ui-polish-level3/requirements.md) と同じ考え方とする）。
- REQ-4.3: システムは、インラインの戻るボタンを撤去した後の `.view__header`（設定画面の見出し、生物検索画面の「生物一覧」ボタン）のレイアウトが破綻しない状態にするものとする。
- REQ-4.4: システムは、本変更によって既存の重なり合うUI（一覧画面のメニューパネル、入力フォーム画面の過去値ピッカーのパネル）の重なり順・表示位置を壊さないものとする。
- REQ-4.5: システムは、幅320 CSSピクセル以上の縦向き画面において、本変更により横スクロールを発生させないものとする（[mobile-compatibility REQ-6.4](../mobile-compatibility/requirements.md)）。
- REQ-4.6: モーダル（[写真の拡大表示](../photo-lightbox/requirements.md)・[サイン入力](../signature-fullscreen/requirements.md)）を開いている間、システムはフローティング戻るボタンをモーダルより前面に表示せず、かつ操作できない状態に保つものとする（[photo-lightbox REQ-2.3, REQ-6.3](../photo-lightbox/requirements.md)）。
- REQ-4.7: システムは、ソフトウェアキーボードが表示されている状態（生物検索画面の検索欄への入力中）においても、フローティング戻るボタンが入力欄・既存の操作要素を覆って操作を妨げる状態にしないものとする（→ [設計 9](./design.md#9-既知のトレードオフリスク)）。

### 5. アクセシビリティ

- REQ-5.1: システムは、フローティング戻るボタンにアクセシブルな名前「戻る」を与えるものとする（対象3画面で共通とする）。
- REQ-5.2: システムは、フローティング戻るボタンをキーボード操作で到達・実行可能とし、フォーカス位置が視覚的に判別できる状態にするものとする。
- REQ-5.3: システムは、フローティング戻るボタンのDOM上の位置を当該画面の主要コンテンツより前とし、キーボードのTab順・支援技術の読み上げ順が現行のインラインの戻るボタン（`.view` の先頭）と同じ相対順序になるものとする。
- REQ-5.4: システムは、フローティング戻るボタンの意味をピクトグラムのみに依存させないものとする（表示テキストを持たない場合は、アクセシブルな名前で意味を伝えるものとする。[ui-polish-level1 REQ-3.2, REQ-3.6](../ui-polish-level1/requirements.md)、[ui-polish-level3 REQ-1.7](../ui-polish-level3/requirements.md) のFABと同じ扱いとする）。
- REQ-5.5: システムは、本仕様で用いるピクトグラムを既存の `src/components/icons.tsx` と同一の方式（インラインSVG・単色・文字色追従・文字サイズ追従・支援技術から除外）で提供するものとし、外部のアイコンライブラリ・Webフォント・外部ホストの画像を導入しないものとする（[ui-polish-level1 REQ-3.2〜REQ-3.5](../ui-polish-level1/requirements.md)）。
- REQ-5.6: システムは、フローティング戻るボタンの表示テキストと背景のコントラスト比を4.5:1以上、アイコン・境界などの非テキスト要素のコントラスト比を3:1以上に保つものとする（[mobile-compatibility REQ-6.5](../mobile-compatibility/requirements.md)、[ui-polish-level1 REQ-5.4](../ui-polish-level1/requirements.md)）。
- REQ-5.7: システムは、フローティング戻るボタンの配色をOSのダークモード設定に追従させるものとする（[ui-polish-level2](../ui-polish-level2/requirements.md) の配色トークンを用いるものとする）。

### 6. 非機能・回帰防止

- REQ-6.1: システムは、本変更のために依存パッケージ（UIコンポーネントライブラリ・ルーティングライブラリ等）を新規に追加しないものとする。
- REQ-6.2: システムは、本変更によって保存されるデータ・データモデル・Dexieのスキーマ・[Google Drive同期](../google-drive-sync/requirements.md)の形式および `schemaVersion` を変更しないものとする。

## 確定事項（ユーザー確認済み）

以下はいずれも 2026-08-15 にユーザー確定済み。各案の比較・根拠は [設計](./design.md) の該当節を参照。

1. **表示位置**（REQ-1.4。[設計 2-2](./design.md#2-2-表示位置確定コンテンツ列の左上)）: **確定＝コンテンツ列の左上に固定（推奨案A どおり）**。iOS / Android のネイティブアプリの戻る導線と同じ位置で発見しやすく、現行のインラインボタンの位置（画面先頭）とも一致するため移行の違和感が小さい。画面下部の既存の操作行（詳細画面の「編集」「削除」）やiOS Safariの下部ツールバーと場所を奪い合わない。トレードオフとして、片手・親指では届きにくく、スクロール中は本文の左上を常に覆う。
2. **見た目**（REQ-1.13, REQ-5.4。[設計 3](./design.md#3-見た目確定アイコンのみの円形ボタン)）: **確定＝アイコンのみの円形ボタン（44px、`ChevronLeftIcon`）＋ アクセシブルな名前「戻る」（推奨案ア どおり）**。FAB（[ui-polish-level3 REQ-1.7](../ui-polish-level3/requirements.md)）と同じ扱いで、本文を覆う面積が最小になる。背景は不透明（`--surface`）とし、境界線と影で浮いていることを示す（REQ-1.8）。トレードオフとして、表示テキストが消えるため文字を頼りにしているユーザーには発見性がやや下がる。
3. **入力フォーム画面（`DiveLogFormView`）の扱い**（REQ-3.4, REQ-3.6。[設計 7-4](./design.md#7-4-入力フォーム画面対象外)）: **確定＝対象に含めない（推奨案とは異なる結論）**。入力フォーム画面は現行のインラインの「← キャンセル」を据え置く。**理由: 未保存の入力に対する確認ダイアログが現状存在せず（REQ-2.4）、縦に長いフォームの上に常時「キャンセル」が浮いていると誤タップによる入力喪失リスクが高まるため**。この結果、入力フォーム画面だけ戻る導線の見た目・位置が異なる状態になるが、意図した例外として受け入れる。
4. **読み込み中・記録が見つからない状態での表示**（REQ-3.5）: **確定＝本仕様に含める（推奨どおり）**。ただし対象は本機能の対象3画面に限る。**入力フォーム画面の「読み込み中...」状態の行き止まりは、3の決定により本仕様のスコープ外**とする（[スコープ](#対象外今回やらないこと)）。
5. **既存の `.view__header` の整理方法**（REQ-4.3。[設計 7](./design.md#7-各画面の差分)）: **確定＝設定画面は `.view__header` を外して `h1` 単独にし、生物検索画面（該当ログ一覧）は「生物一覧」ボタンを右寄せのまま維持する（推奨どおり）**。
