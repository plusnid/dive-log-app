# 要件: UI仕上げ レベル1（情報の強弱・余白・アイコン）

関連: [設計](./design.md) / [概要](../00-overview.md) / [ダイビングログCRUD](../dive-log-crud/requirements.md) / [モバイル対応](../mobile-compatibility/requirements.md)

## 概要

一覧画面のログカードを中心に、**表示（見た目）だけ**を整える改善。目的は「1枚のカードを一目見たときに、いつ・どこで潜ったのかが最初に伝わり、水深や時間などの数値が読み取りやすい」状態にすること。

改善案は3段階（レベル1〜3）で提示されたうち、本仕様は**レベル1（文字とレイアウトの微調整）だけ**を対象とする。

レベル1の内容:

1. 情報の強弱をつける（日付とダイビングポイント名を最も目立たせる／ラベルよりデータ本体を引き立てる）
2. 余白を均等にする（カード内のパディングを広げる）
3. アイコンの統一（「最大水深」「潜水時間」などにピクトグラムを付ける）

## スコープ

### 対象

| 対象 | ファイル | 適用する改善 |
| --- | --- | --- |
| 一覧のログカード | `src/components/DiveLogListItem.tsx` / `.css` | 1・2・3 すべて |
| 詳細画面の見出し（ポイント名・日付） | `src/views/DiveLogDetailView.tsx` / `src/App.css` | 1（一覧カードと同じ強弱方針に揃える） |
| 詳細画面の項目ラベル（`dt` / `dd`） | `src/App.css` | 1（色指定のトークン化とコントラスト調整のみ） |
| 共通の文字色トークン | `src/index.css` | 1（ラベル用の淡色トークンを追加） |

### 対象外（今回やらないこと）

- **レベル2**: テーマカラー（海の青系など）の変更、フォントファミリの変更、カード内への写真プレビュー表示
- **レベル3**: 「新規記録」ボタンのFAB化、ナビゲーションの再構成、入力方法のセグメントコントロール化
- 入力フォーム画面（`DiveLogFormView`）・同期設定画面（`SyncSettingsView`）・インストール案内（`InstallGuide`）の見た目
- 詳細画面の各項目（`dl` 内）へのアイコン付与（→ [未確定事項](#未確定事項確認したい点) 4）
- 一覧の情報項目そのものの増減・並び順の変更（[dive-log-crud REQ-1.3, REQ-1.5, REQ-1.6](../dive-log-crud/requirements.md) は維持）

## 用語

- **ラベル**: 項目名を表す文字列（例: 「最大水深」「潜水時間」）
- **データ本体**: 値と単位（例: 「20m」「45分」）
- **メタ行**: 一覧カードの下段に並ぶ、最大水深・潜水時間・写真枚数・サイン済マークの行

## 要件（EARS形式）

### 情報の強弱（一覧カード）

- REQ-1.1: システムは、一覧カードのダイビングポイント名を、同じカード内のどのテキストよりも大きい文字サイズかつ太字で表示するものとする。
- REQ-1.2: システムは、一覧カードの日付を、メタ行のどのテキストよりも大きい文字サイズで、かつ本文と同じ濃さの文字色で表示するものとする（ラベルと同じ淡色にはしない）。
- REQ-1.3: システムは、一覧カード内の視覚的な強さを「ダイビングポイント名 > 日付 > データ本体 > ラベル・エリア名」の順とするものとする。
- REQ-1.4: システムは、メタ行のラベルを、同じ行のデータ本体より小さい文字サイズかつ淡い文字色で表示するものとする。
- REQ-1.5: システムは、メタ行のデータ本体を、本文と同じ濃さの文字色で表示するものとする。
- REQ-1.6: システムは、メタ行の各項目をラベルとデータ本体に分けて出力し、それぞれに異なる書式を適用できるものとする。
- REQ-1.7: システムは、一覧カードに表示する情報の種類・順序・表示条件（値が存在する場合のみ表示する等）を現行から変更しないものとする。
- REQ-1.8: エリア名が表示されるとき、システムはエリア名をダイビングポイント名より小さい文字サイズかつ淡い文字色で、ダイビングポイント名の直前に併記するものとする（現行の位置・区切り表現を踏襲する）。
- REQ-1.9: ダイビングポイント名が1行に収まらないとき、システムはカードの幅を超えずに折り返して全文を表示するものとする（省略記号による切り詰めは行わない）。

### 余白（一覧カード）

- REQ-2.1: システムは、一覧カードの内側パディングを現行（上下 0.75rem / 左右 1rem）より広げ、上下左右の余白が視覚的に均等に見える値を用いるものとする。
- REQ-2.2: システムは、カード内の各行（日付・ポイント名・メタ行）の間隔を、情報のまとまりが読み取れる値に調整するものとする。
- REQ-2.3: システムは、メタ行の各項目間に、項目どうしが1つの塊に見えない程度の間隔を確保するものとする。
- REQ-2.4: 余白の変更後も、システムはカード全体のタップ領域を最小44×44 CSSピクセル以上に保つものとする（[mobile-compatibility REQ-6.3](../mobile-compatibility/requirements.md)）。
- REQ-2.5: 余白の変更後も、システムは画面幅375px（小型スマートフォン相当）および640px（`#root` の最大幅）において横スクロールを発生させないものとする。メタ行の項目は必要に応じて折り返すものとする。

### アイコン（一覧カード）

- REQ-3.1: システムは、メタ行の各項目（最大水深・潜水時間・写真枚数・サイン済）の先頭に、その項目を直感的に表すピクトグラムを表示するものとする。
- REQ-3.2: システムは、ピクトグラムを装飾として扱い、支援技術（スクリーンリーダー）の読み上げ対象から除外するものとする。項目の意味はテキストで併記し続けるものとする。
- REQ-3.3: システムは、ピクトグラムを単色で描画し、隣接するテキストの文字色および文字サイズに追従させるものとする。
- REQ-3.4: システムは、同一カード内のすべてのピクトグラムを同一の描画方式・線の太さ・大きさで統一するものとする（現行の絵文字「📷」「✔」も同じ体系に置き換える）。
- REQ-3.5: システムは、ピクトグラムの表示のために外部のアイコンライブラリ・Webフォント・外部ホストの画像を新規に導入しないものとする（[概要 NFR-1](../00-overview.md) および [offline-pwa](../offline-pwa/requirements.md) のオフライン動作を損なわないため）。
- REQ-3.6: ピクトグラムが表示できない環境であっても、システムは各項目の意味と値をテキストのみで判別できる状態に保つものとする。

### 詳細画面

- REQ-4.1: システムは、詳細画面のダイビングポイント名（見出し）と日付・開始時刻（サブタイトル）に、REQ-1.1〜REQ-1.3 と矛盾しない強弱を適用するものとする。
- REQ-4.2: システムは、詳細画面の項目ラベル（`dt`）の淡色表示を維持し、色の指定を共通トークンに置き換えるものとする。見た目の変更はコントラスト基準（REQ-5.4）を満たすための微調整に留めるものとする。
- REQ-4.3: システムは、詳細画面の項目一覧（基本情報・環境情報・器材/エア管理）にピクトグラムを追加しないものとする。
- REQ-4.4: システムは、詳細画面に表示する項目・文言・「-」による未入力表現を変更しないものとする（[dive-log-crud REQ-3.1, REQ-3.2, REQ-6.11](../dive-log-crud/requirements.md) を維持）。

### 非機能・回帰防止

- REQ-5.1: システムは、本改善によってデータモデル・DBスキーマ・保存される値・リポジトリのAPI・同期対象データのいずれも変更しないものとする（表示層のみの変更）。
- REQ-5.2: システムは、変更後の一覧カードおよび詳細画面の配色を、OSのダークモード設定に追従させるものとする（[mobile-compatibility REQ-6.5](../mobile-compatibility/requirements.md)）。
- REQ-5.3: システムは、入力要素（`input` / `select` / `textarea`）の文字サイズを縮小しないものとする（[mobile-compatibility の既知の制約](../mobile-compatibility/design.md#既知の制約リスク)にあるiOS自動ズーム課題を悪化させないため）。文字サイズの縮小は入力要素以外の表示テキストに限るものとする。
- REQ-5.4: システムは、淡色で表示するテキスト（ラベル・エリア名・サブタイトル）の文字色と背景色のコントラスト比を、ライトモード・ダークモードのいずれでも4.5:1以上に保つものとする。
- REQ-5.5: システムは、一覧カードの選択（詳細画面への遷移）・キーボード操作・フォーカス表示の挙動を変更しないものとする（[dive-log-crud REQ-1.4](../dive-log-crud/requirements.md)）。

## 未確定事項（確認したい点）

以下はユーザー判断が必要、または実装前に合意しておきたい点。設計上の推奨案は [設計](./design.md) に記載する。

1. **一覧カードの行構成**: 現行は「日付（左）／エリア名・ポイント名（右）」の1行 + メタ行の2段構成。ポイント名を大きくすると右寄せの大きな文字になりバランスが崩れるため、設計では「日付」「エリア名・ポイント名」「メタ行」の縦3段（すべて左揃え）を推奨する。現行の左右2カラムを維持したまま文字サイズだけ変える案も可能。どちらを採用するか要確認。
2. **ダークモード時のカード配色**: 現行の `DiveLogListItem.css` はカード背景 `#fff`・枠線 `#ddd`・文字 `#555` / `#777` をハードコードしており、ダークモードでは白カードに淡色文字となって [mobile-compatibility REQ-6.5](../mobile-compatibility/requirements.md) を満たしていない。REQ-5.2 / REQ-5.4 を満たすには既存のCSS変数（`--surface` / `--border`）への置き換えが必要となる。これは「レベル2のテーマカラー変更」ではなく既存要件への適合修正と整理しているが、見た目が変わるため要確認。
3. **アイコンの実装方式**: インラインSVG（推奨）か絵文字か。設計では、プラットフォーム間の見た目差が大きい絵文字ではREQ-3.4「統一」を満たしにくいため、依存追加のないインラインSVGを推奨する。あわせて既存の「📷」「✔」も置き換える前提。
4. **詳細画面のアイコン**: 今回は対象外（REQ-4.3）としている。器材・環境の全項目に破綻なくアイコンを割り当てるのは難易度が高く、一覧カードでの効果を確認してから判断したいため。詳細画面の基本情報（最大水深・潜水時間）だけ揃える案もあり得る。
5. **メタ行のラベル省略**: 「最大水深 20m」を「（波アイコン）20m」のようにアイコンでラベルを置き換える案もあるが、意味の伝達がアイコンのみに依存しREQ-3.6と両立しないため、本仕様ではラベルを残す前提とする。
